# Config.md — AI Video Avatar Output Contract

**Status:** binding source of truth for every avatar asset shipped to
`forgotten-mistory.web.app`. The n8n workflow *AI Video Avatar Studio* embeds these
values as constants and **fails the run** rather than publishing anything that drifts
from them.

**Provenance:** every number in §1 was measured with `ffprobe` against the assets
currently deployed in `public/assets/` on 2026-09-03. Nothing here is estimated.

**Architecture, 2026-09-04 — OpenRouter only.** ElevenLabs and D-ID are out of scope.
The ElevenLabs key authenticates but the account tier reports
`can_use_instant_voice_cloning: false`, so text-to-speech returns `401 ivc_not_permitted`
on any key; D-ID returns `403 explicit deny in an identity-based policy`. Both are
plan-level denials that no key rotation fixes. Every AI-video capability now comes from
the OpenRouter key in `~/.claude/.env.production` and nothing else. The consequence for
narration is stated in §1.4a and is not negotiable.

### 1.4a Narration provenance under the OpenRouter-only architecture

§1.4 records the voice on the **deployed** asset. It is **not** the voice on anything the
workflow now generates.

- OpenRouter exposes `POST /api/v1/audio/speech`, but the endpoint resolves **zero**
  models — verified against 24 candidate model ids plus a nonsense control, which failed
  identically. There is no text-to-speech and no voice-cloning surface on OpenRouter.
- Generated narration is therefore a **HeyGen built-in voice**, selected at the brief
  form and passed as `provider.options.heygen.voice_id`.
- `voice_is_cloned` is `false` by construction on every run. The workflow emits advisory
  `VOICE-1` on every asset and the reviewer restates it. **A generated asset must never be
  published as Vik speaking in his own voice.** This is a provenance rule, not a
  quality one, and it does not expire when a better model appears.

### 1.5 Presentation box (`app/globals.css`)

- `.avatar-placeholder` **520 × 650** desktop, **340 × 440** mobile
- video/still rendered `object-cover` inside `.avatar-circle`

> **Consequence — framing rule.** The box is portrait (≈4:5) but the source is 16:9,
> so the left and right thirds are **cropped away on every viewport**. The subject's

## 2. The contract every generated avatar must satisfy

### 2.1 Web delivery profile (`WEB_PARITY`) — hard requirement

Exactly matches §1.1/§1.2. This is what may be committed to `public/assets/`.

| Property | Required value | Tolerance |
|---|---|---|
| container | `mp4` (faststart) | none |
| video codec | `h264`, profile `High` | none |
| pixel format | `yuv420p` | none |
| frame rate | `24/1` | none — exact |
| aspect ratio | `16:9` | none |
| dimensions | `1280×720` (master) · `640×360` (hero) | exact |
| audio (hero loop) | **none** | must be stripped |
| audio (spoken clip) | `aac`, 48 kHz, mono | codec exact |
| max file size | 500 KB (hero) · 5 MB (spoken) | hard fail above |
| colour | `bt709` primaries/transfer/matrix, tagged | none |

Rationale for the 500 KB hero cap: `CLAUDE.md` "Definition of done" — *no asset >500KB*,
Lighthouse mobile perf ≥ 90, LCP < 2.5 s.

### 2.2 Master profile (`MASTER_1080`)

`1920×1080` · `24/1` · `h264 High` · `yuv420p` · AAC 48 kHz. Archive/edit source.

### 2.3 UHD profile (`UHD_4K`)

`3840×2160` · `24/1` · `yuv420p` · AAC 48 kHz. Archive only — **never** shipped to the
site, because it breaches §2.1's size budget by orders of magnitude.

#### 3.0a Native frame rate — measured, and mostly unmeasured

No model in this catalogue accepts an output frame-rate parameter. The rate is whatever
the model emits, so §2.1's exact `24/1` requirement can only be met natively by accident.

| Model | Native fps | Basis |
|---|---|---|
| `heygen/avatar-iv` | **25** | measured by byte-level MP4 parse on four separate real renders (executions 15, 18, 21, 22) — never once 24 |
| every other model | *unmeasured* | not probed on this account; an unmeasured frame rate is not a fact and the workflow records it as `null`, not as a guess |

The planner publishes this before any spend. For `heygen/avatar-iv` the approval form
states plainly that the render **will** fail `CONFIG-2` and that the run will stop at a
deterministic conform step. For every other model it states that conformance is unverified
until the render is probed. Neither statement is a prediction dressed as a fact.

### 3.1 The 4K finding — recorded deviation

**None of the seven models above can emit true UHD.** The ceiling is 1080p (wan / veo-lite
/ avatar-iv), 768p (hailuo-3-max) or 720p (seedance-2.0-mini / 2.5). Verified by live
catalogue probe, not inference.

`UHD_4K` is therefore reached by one of two **verified** routes, selected automatically:

1. **Native 4K tier** — `google/veo-3.1` or `bytedance/seedance-2.0`. Both list
   `3840x2160` literally in `supported_sizes` (not merely the coarse `"4K"` label),
   so the resolution is asserted by the API itself. Same model families the brief
   names, full-size variants.
2. **Upscale tier** — generate at the model's native ceiling, then
   `black-forest-labs/flux-video-upscale` with `upscale_factor: 2`
   (1080p → 2160p = exactly 4K). Supports 1.5–3×; requires an
   `input_references` entry of `type: video_url`.

### 3.2 avatar-iv request contract (probed, exact)

- **`audio_url` references accept HTTPS only.** A `data:` URI and a plain `http://`
  URL are both rejected with `Invalid reference URL: input_references[N].audio_url.url:
  Only HTTPS URLs are allowed`. Verified per reference type, not assumed: an
  `image_url` reference passes this same validation stage with a `data:` URI, so the
  restriction is specific to audio. Under the OpenRouter-only architecture the workflow
  sends no `audio_url` at all: it supplies a `prompt` plus a HeyGen `voice_id`, so this
  constraint is recorded for completeness rather than exercised.
- Requires an `image_url` reference **and** either a `prompt` (script) **or** an
  `audio_url` reference. Both-absent → `400`.
- `frame_images` is **not supported** (`does not support first_frame frame_images`).
- Passthrough is **`provider.options.heygen`**, not `provider.heygen`. The shorter path is
  accepted by the API and then silently ignored, which presents as a missing-voice error.
  Keys: `voice_id`, `voice_settings`, `motion_prompt`, `expressiveness`, `fit`,
  `remove_background`, `background`, `caption`, `title`.
- With a text `prompt` (rather than an `audio_url`), `provider.options.heygen.voice_id`
  is **required**.
- `expressiveness` is the enum `high` | `medium` | `low`. A float is rejected with
  `Input should be 'high', 'medium' or 'low'` — a `400` before billing, so the run costs
  nothing, but it costs the run.
- `fit` is `contain` | `cover`. `caption` must be an object, not a boolean.
- There is **no `duration` parameter**. Runtime, and therefore cost, is set by the length
  of the narration, which is why the plan is re-costed from the finished script before the
  approval form is shown.

### 3.4 The measurement instrument is itself verified

The gate parses the MP4 container byte-by-byte in pure JavaScript — there is no ffmpeg
inside the n8n runtime. That parser was wrong on first build: it read width/height from
the VisualSampleEntry's reserved `pre_defined[3]` block and reported **0x0** for every
video, which would have failed every asset forever for a reason that had nothing to do
with the video.

Corrected offsets, per ISO/IEC 14496-12 and confirmed against a real file:

- VisualSampleEntry `width`/`height` at `entry+32` / `entry+34`
- child boxes (`avcC`) begin at `entry+86`
- `tkhd` `width`/`height` at `+76` (version 0) / `+88` (version 1)
- `mdhd` timescale/duration and `stsz` sample_count were already correct

The deployed code, extracted from the live n8n database and run unmodified under plain
`node` against a 5,542,404-byte avatar-iv render, now agrees with `ffprobe` on every
field: `1280x714`, `h264`, `High`, `yuv420p`, `25 fps`, `12.36 s`, `aac`. A conformance
gate whose instrument is unverified is theatre; this one is calibrated.

## 4. Conformance gate (mechanical, blocking)

Every generated asset is measured and compared field-by-field against §2.1. The run is
marked `NON_CONFORMANT` and **publication is blocked** if any of these fail:

1. `width × height` ≠ target
2. `r_frame_rate` ≠ `24/1`
3. `codec_name` ≠ `h264` or `profile` ≠ `High`
4. `pix_fmt` ≠ `yuv420p`
5. file size > profile budget
6. hero variant carries an audio stream
7. subject centroid outside the central 56 % width band (§1.5 framing rule)

There is no "close enough". Requirement: *0 regression, 0 drift.*

### 4.1 Defect classification — which repair can actually work

A failed check is still a failure. Classification changes **the repair**, never the verdict.

| Defect | Class | Why |
|---|---|---|
| `CONFIG-0` unmeasurable container | `UNMEASURABLE` | nothing to repair; the asset is not evidence |
| `CONFIG-1` dimensions, aspect already correct | `CONFORM` | a pure scale is deterministic and crops nothing |
| `CONFIG-1` dimensions, aspect wrong | `REGENERATE` | conforming would crop the subject or pad the composition |
| `CONFIG-2` frame rate | `CONFORM` | no request parameter sets it; only a transcode changes it |
| `CONFIG-3` codec · `CONFIG-4` profile · `CONFIG-5` pixel format | `CONFORM` | a transcode sets all three exactly |
| `CONFIG-6` size budget | `CONFORM` | a bitrate cap bounds output size by construction |
| `CONFIG-7` aspect | `REGENERATE` | see `CONFIG-1`; the crop box would cut the subject |

When **every** measured defect is `CONFORM`-class **and** the independent reviewer raises
no script defect, the run terminates at `Halt - Conform Required` carrying the exact
command, and **spends no retry attempt**. Regenerating a script cannot change a container
frame rate; spending an attempt on it is guaranteed waste. Before this rule existed, an
`avatar-iv` run burned three attempts at roughly $0.34 each on a defect no rewrite could
reach.

### 4.2 The conform step

Emitted per candidate, with the filter chain built from the defects actually measured and
the bitrate cap derived from the profile budget over the measured duration:

```
ffmpeg -y -i "<content_url>" -vf "fps=24,format=yuv420p" \
  -c:v libx264 -profile:v high -level:v 3.1 -preset slow \
  -crf 20 -maxrate <cap>k -bufsize <2*cap>k -r 24 \
  -c:a aac -b:a 128k -ar 48000 -movflags +faststart <out>.mp4
```

Verified, not asserted. A synthetic 1280×720 @ 25 fps `h264 High yuv420p` clip with AAC
audio was built to match the measured render, the emitted command was run against it
verbatim, and `ffprobe` on the result reported `r_frame_rate=24/1`, `avg_frame_rate=24/1`,
`1280×720`, `h264 High`, `yuv420p`, `aac` 48 kHz preserved, 2,753,960 bytes against the
5,242,880 ceiling. Duration moved 6.960 s → 6.976 s, inside one frame period, so audio is
not re-timed and lip sync holds.

The conform output must be **re-probed against §2.1 before publication**. The command is
a repair, not a certificate.

## 5. Content contract

### 5.1 Banned register — hard fail

No defensive or apologetic delivery. The script is rejected, deterministically, on any
of: `sorry`, `apolog*`, `I'm just`, `I'm only`, `unfortunately`, `I'm afraid`,
`disclaimer`, `I can't really`, `I'm not an expert`, `hopefully`, `I might be wrong`,
`please forgive`, `bear with me`, `to be honest`, `I hope this helps`.

### 5.2 Required register

Each video explains **one genuinely difficult or esoteric concept**, delivered from
demonstrated experience. Declarative, evidence-led, numbers over adjectives. Restrained —
`CLAUDE.md` NN-3 forbids boastful or superlative copy, and that rule governs the avatar's
speech exactly as it governs the site's text.

### 5.2a Narration length — the measured floor

Script length is one number, published by the planner and enforced by the register gate,
so the prompt and the gate cannot drift apart: budget = `duration_seconds / 60 × 150`
words, hard ceiling = `ceil(budget × 1.15)`.

Below roughly **38 words the content contract cannot be satisfied at all.** §5.2 asks for
four things — the counter-intuitive claim, why the concept is hard, a concrete grounding
detail, and the operational consequence — and they do not fit in fewer.

Measured, not assumed. At a 20-word budget (8 s target) the independent reviewer rejected
two consecutive drafts for vagueness while both sat at the 23-word ceiling; at a 38-word
budget (15 s) it raised no vagueness finding. The register gate and the reviewer are then
in direct opposition: the words the reviewer wants are words the gate forbids, and the run
cannot converge no matter how well it is written.

Two consequences, both mechanical:

- The planner warns **before spend** when the budget falls below 38 words, naming the
  evidence.
- The refinement loop stops when the reviewer returns script defects while two consecutive
  drafts sat within two words of the ceiling, and names the duration as the binding
  constraint instead of spending another attempt on prose that cannot fit.

### 5.2b Review integrity — a parsed verdict is not a verdict

The independent review is the only check on anything the deterministic gate cannot
measure, so its **absence must never read as approval**.

Execution 21 proved this is not theoretical. The reviewer's structured-output parser had
auto-fix enabled; when the model's first answer failed to parse, auto-fix re-prompted it
to repair its own output **without the evidence in front of it**, and it returned a
perfectly schema-valid object reading `verdict: "Unknown"`, `confidence: 0`, `evidence:
"No evidence available due to missing input."` A shape-only usability check passed it, and
the conform route opened on a review that never happened.

The rules that follow from it:

1. **Auto-fix is never enabled on a judgement.** A malformed review fails loudly to
   `Halt - Review Unavailable`. Repair is a full retry of the review with the evidence
   intact, never a patch of its output. Auto-fix **is** enabled on the script parser,
   because a repaired script is still judged afterwards by the register gate and the
   reviewer, whereas a repaired judgement is judged by nobody.
2. A review counts only if it carries the marks of a real judgement: a verdict of
   `CONFIRMED` or `REJECTED`, a confidence above zero, and at least 20 characters of
   evidence. Anything else sets `review_usable: false`, which blocks publication **and**
   the conform route.
3. The reviewer files each finding as a **script defect** (a rewrite fixes it) or a
   **container defect** (only a transcode fixes it), never both, and is asked to challenge
   the pipeline's own `CONFORM`/`REGENERATE` classification as a claim rather than accept
   it as evidence.

### 5.3 Virtues encoded as machine checks

| Virtue | Mechanical expression |
|---|---|
| consistency | §2.1 byte-level profile equality across every generation |
| skill | adversarial review must return CONFIRMED **and be usable** per §5.2b |
| patience | poll to true completion; never a partial or timed-out asset |
| nobility | §5.1 register ban; no self-deprecation, no puffery |
| predictability | fixed `seed` per concept; identical inputs → identical output |

## 6. Approval

Generation is **gated on Vik's explicit approval**. The workflow pauses at a form
showing the resolved plan, per-model parameters, the re-costed spend against the ceiling,
and every advisory — including the frame-rate disclosure of §3.0a and the content-budget
warning of §5.2a. No approval → no spend, no generation, no publication.

Publication to production is a **second** approval, taken after the asset has been
measured and reviewed. Everything between the two is autonomous: script composition,
bounded script rewrites on a register violation, dispatch, polling, download, byte-level
measurement, conformance grading, independent adversarial review, and the routing of each
defect class to the only repair that can fix it.

Terminal states, all of which publish nothing:

| Terminal | Meaning |
|---|---|
| `Halt - Preflight Failed` | the OpenRouter key or video surface is not usable |
| `Halt - Register Violation` | the script failed the register gate and the 2-rewrite budget is spent |
| `Halt - All Renders Failed` | every dispatch or render failed; per-model errors reported |
| `Halt - Review Unavailable` | no usable independent verdict exists (§5.2b) |
| `Halt - Conform Required` | measured non-conformant, but only by `CONFORM`-class defects; carries the exact command (§4.2) and spends no retry |
| `Halt - QA Not Met` | rewrites exhausted, spend ceiling reached, or the duration is the binding constraint (§5.2a) |

An honest failure is a sanctioned outcome. None of these is reached by relaxing a check.
